# wiki

The Rust workspace of shenron: the `shenron` CLI, MCP server, API, C ABI, studio and the Koharu engine crates.

## Why

Shenron is a Bun repository; its Rust crates live here so they build as one Cargo workspace. The Bun side (site, bot, packages) and the canonical `data/` belong to [aphrody-labs/shenron](https://github.com/aphrody-labs/shenron). No Bun package lives here.

## Install

Three checkouts side by side: `src/wiki` (shared `aphrody-*` core + `shenron-*` crates), `src/shenron` (provides `data/`), and `src/nie` (IEVR only). The Rust toolchain is pinned in `rust-toolchain.toml`. Builds run on the build host, not on a workstation.

## Usage

```sh
cargo run -p shenron-cli -- --help   # the `shenron` command
cargo xtask map                      # MAP.tsv: areas, files, bytes, gate per area
```

Per-crate commands are in each `crates/<name>/README.md`.

## Documentation

`Cargo.toml` declares `members = ["crates/*"]` and excludes three standalone crates, so the 42 directories of `crates/` give 39 workspace members:

| Family              | Crates                                                                 |
| ------------------- | ---------------------------------------------------------------------- |
| `shenron-*` (25)    | api, cli, mcp, ffi, engine, lexicon, rag, memory, studio, edge, ...    |
| `koharu-*` (15)     | agent, app, canvas, desktop, library, ml, pipeline, psd, renderer, ... |
| `dragon-pixel`      | WebGPU game view and multiplayer room service                          |
| `xtask`             | repository tasks (`cargo xtask map`)                                   |

Excluded (own `Cargo.lock`, build alone): `shenron-video`, `shenron-tv`, `shenron-deployd`.

`replica/` holds product recon, plans and schemas for dragonballfr.com (no crate reads it).

### Data contract with shenron

Crates read canonical data from the sibling shenron checkout through one variable,
`SHENRON_DATA_DIR`, set in `.cargo/config.toml` to `../shenron/data` (resolved from this root).
Embedded files use `include_str!(concat!(env!("SHENRON_DATA_DIR"), "/..."))`. Tests and tools that
need other shenron files (`packages/api/openapi/public.json`, `templates/agent-home`,
`scripts/parity/states.json`, `apps/bot/tests/rag-gold.jsonl`) take
`SHENRON_ROOT`, defaulting to the parent of `SHENRON_DATA_DIR`. An exported `SHENRON_DATA_DIR` wins over the config.

Outputs flow the other way through shenron env paths (`SHENRON_WIKI_DIR`): the TypeScript generated by
`shenron-ffi` is committed in `crates/shenron-ffi/generated` (`UPDATE=1 cargo test -p shenron-ffi --test typescript`
rewrites it) and copied by shenron's `packages/native/scripts/generate.ts`.
